## Design

| File | Owns |
|---|---|
| `story/fight/fight_side.gd` | One side of one exchange: inputs (stance, breath/weapon dice, scores, armour blocks, abilities, Nerves target) and results (threat, losses, chosen/spare/failed/blocked weapon dice, impairments, injury, damage prevented) |
| `story/fight/fight_exchange.gd` | **Pure resolver** (no randomness): threat → vantage / stance hooks (Nerves) → dice checks (losses, weapon die: best free one or the chosen one, armour) → damage (stances → shield → Gambeson) |
| `story/fight/stances/` | `FightStance` strategies on `CharacterAttribute.fight_stance` (Guts / Blood / Nerves); pure hooks because `Rules` preloads attributes |
| `story/fight/fight.gd` | Fight across exchanges: outcome, incapacitation flags, the exchange being applied (weapons, lost dice), `exchange_steps` (default `exchange_steps.tres`), `start_exchange` + `get_current_step()` / `advance()` + `end_exchange()` (outcome), summary paragraphs (`tell`), condition text |
| `story/fight/steps/` | Exchange steps as stateless **resources** (strategies): `ExchangeStep` (`side`: player / monster; `enter(fight)` applies its part and returns its paragraph, `applies(fight)` lets it be skipped). `DiceStep`, `TieStep` (equal threats, both sides), `UnnervingStep`, `WeaponCheckStep`, `BreathDiceStep`, `VantageStep` (Guts bonus / Blood reduction), `ArmorStep`, `InjuryStep`, `IncapacitationStep` (monster rolls in `enter`, player via `resolve(fight, success)`). One `.tres` per step and side, order in `exchange_steps.tres` (`ExchangeSteps`). The outcome is no step: `Fight.end_exchange()` |
| `story/messages/fight_request.gd` / `fight_result.gd` | Player input (weapon, stance, dice, flee, Nerves target) → both `FightSide`s (abilities, extra weapon dice, armour; shields not raised) |
| `story/story.gd` | Fight choices, exchange pages; **no awaits**: each step is one queued event that applies and presents it (by class and side), then queues `queue_until` typing, the pause and the next step. The player's save page stops the chain; its roll continues it |
| `story/story_page.gd` | `fight` marks exchange pages; `is_fighting()` (also disables resting in `Mechanics`) |
| `characters/monsters/` | `Monster` (Node) + `Monsters` (identity: spawning page, profile, index); `MonsterProfile` (scores, breath dice, weapons/armour/shields, one `equipment_modifiers` list, `attack`); `attacks/` (`GutsAttack`, `NervesAttack`) |
| `story/fight/tactics/` | How a side decides on its gear when nobody asks the player: `WeaponTactic` (`Cautious` default: best free die / `Reckless`: forces), `ShieldTactic` (`Cautious` default: raises unless forced / `Reckless`), `ArmorTactic` (`Sparing` default: most unmarked results, marks before ruining). Exported on `MonsterProfile` (none = default), carried on `FightSide` |
| `characters/equipment/`, `weapons/`, `armor/`, `shields/`, `items/` | Profile pattern: authored `XProfile` → runtime `X` (`Equipment`: marks, ruin); `EquipmentModifier`s (battered) |
| `characters/abilities/` | `Ability` strategies on `Origin.abilities` (`modify_vantage`, `get_extra_weapon_dice`, `modify_lost_breath_dice`); `AttributeScoreModifier` is one |
| `game/breath_dice/`, `dice/dice_log/` | Weapon + Nerves target pickers, threat line; log line (threats at DICE, colours at CONSEQUENCES) |

**Outcome → story:** won → `transition` + `consequences`; lost → `failure_transition` + `failure_consequences`; fled → `flee_transition`; draw → `draw_transition`.

## Equipment rework (agreed 2026-10-22)
Weapons and shields work differently on purpose: shields wear with every use, weapons only under strain. "Ruined" = destroyed for good; marks can be restored while resting (later). Marking an already marked face marks the next higher unmarked face instead; with none higher, the item is ruined.
- **Weapons:** within Guts and unmarked: strikes, no mark, no question. Marked face: only if forced; strikes, then marks the next higher face (none: ruined). Above Guts: only if forced; strikes, then **all** faces are marked. Not used: no hit, no mark. Blocked by armour: the hit face is marked (same rule). Several weapon dice (Veteran): the player picks; the choice is only shown when forcing is possible, or always if the player asks for it.
- **Shields:** voluntary. Every raise marks the rolled face; a marked face still blocks, then marks the next higher one (none: ruined). Above Guts: only if forced; blocks, then the shield is ruined.
- **Armour:** worn, not voluntary: a blow it can block is blocked and marks the fitting result. The defender picks the piece among those whose fitting result is unmarked. If all fitting results are marked, the defender picks the piece and either marks its next higher result or ruins it (no higher result: ruined, but it still blocks). The Gambeson keeps its −1 without marks. Attacker choosing the piece is kept for later (one-sided circumstances, e.g. an ambush in the dark).
- **Monsters:** strategies per kind; default uses only what's possible without forcing (armour: mark higher if possible, otherwise ruin).
- **Decisions:** one per kind and exchange, each only when it matters.
- Build order: [x] 1. weapons  [x] 2. shields  [x] 3. armour  [x] 4. monster strategies

## Forcing rework (agreed 2026-10-23)
- **Commit first:** right after the roll, each side commits its weapon die (free, forced, marked face or holding back) and whether it raises its shield (free or forced), measured against its scores before unnerving. Player: one shared panel (weapon die buttons, shield switch defaulting to on when no forcing is needed, confirm); monsters: tactics with exported settings.
- **Threat** = highest of the breath dice and the *free* weapon / shield dice used, minus the overshoot of every forced die (forced dice don't count themselves). Can go below 0; overshoots add up. A tie gives the stances the full threat only if it is above 0.
- **Weapons:** forced above the wield score: marks one face per point of overshoot (rolled face first, then the next higher ones; none left: ruined). Forced on a marked face within the score: no threat cost, the next higher face is marked. Not used: nothing.
- **Shields:** marked only when they actually block damage (rolled face, marked face → next higher). Forced above the wield score: costs the overshoot in threat, no longer ruins.
- **Nerves:** choose a foe attribute. Breath dice rolled with it are also lost if they came up higher than score − vantage; gear wielded with it is **dropped** (gone for the rest of the fight) if its die came up higher than score − vantage. Threat and commitments stay as they are. Forced gear that is dropped has still cost its threat.
- Simulated 2026-10-23 (vs Lurker / strong foe, Guts 5–9, d8–d12): with forced dice counting towards threat, forcing was nearly free (forced die − overshoot = Guts); hence forced dice don't count. Wear per overshoot point: always forcing ruins a d10/d12 in ~3–6 exchanges, forcing at most 2 over in ~13–31.
- Build order: [x] resolver  [x] steps and texts  [x] shared panel  [x] tactics with settings  [x] tests and docs
- Built: `FightExchange._commit` (before the threat, unimpaired scores) → `_get_threat` → Nerves → `_check_dice` (losses, dropped gear via `FightSide.weapon_dropped` / `shield_dropped`, armour) → damage. `CommitStep` (player, first in `exchange_steps.tres`) replaces the weapon and shield choice steps; `FightCommitPanel` is shown in the current entry. `ForcingWeaponTactic` / `ForcingShieldTactic` (exported `max_overshoot`, `force_marked_faces`) replace the cautious / reckless tactics. Dropped gear: `Equipment.dropped`, picked up by `Actor.pick_up_dropped_gear()` when the fight ends.

## Exchange phases (2026-10-25)
- `exchange_steps.tres` (`ExchangeSteps`) only authors the **resolution** (`Array[ResolutionStep]`: unnerving, breath loss, weapon wear, vantage, shield, armour, injury; free order, sides interleaved). `get_steps()` builds the fixed phases around it in code: commit (`CommitStep`) → roll (second side's dice, first side's dice, tie) → resolution → aftermath (second side's save, first side's save). This makes the old crash (a side's breath loss after its incapacitation save) impossible to author. Later: the roll should tell whoever started the fight first (now always the monster).
- The player's armour choice is part of `ArmorStep` (`get_undecided_die`): the story asks before the player's armour step is entered; `ArmorChoiceStep` is gone.

## Watch list
- **Shields: settled (2026-10-22)** on a damage-reducing die that marks with every raise (see Equipment rework). Earlier simulations, kept for reference:
  - Promising: **M-each** (several shield dice, each lowers a different foe die): scales by dice count (1 → 2 → 3 dice ≈ 48 → 68 → 81 % threat wins vs Lurker); dice count = coverage, die size = wield risk. Suggested table if adopted: Buckler 1d6, Round 1d8, Kite 2d6, Pavise 2d8 (3+ dice too strong).
  - Strong but decides fights: lower the **whole** threat by the full result (54–74 %).
  - Too weak / dead: halve threat if shield beats it, cancel the highest die if ≥, cancel exact matches, cancel natural factors of the shield result, extra dice where only the highest/sum acts.
  - Wrong role: shield counts double toward own threat (offence, not protection).
  - 2026-10-19, discard variants (player d4+d6+d8, Sword d10, Guts 7; shield d6–d12, wield vs Guts; win % / damage taken, no shield = 22.8 % / 4.44 vs Lurker, 6.7 % / 6.46 vs 4d10+d10, 22.6 % / 9.04 vs 3d8 natural). H for comparison: 34–42 % / 3.5–3.9, 13–16 % / 5.6–5.9, 38–49 % / 6.4–7.5.
    - **A** discard the highest die ≤ shield: 25–26 % / 3.7–4.0; 7.4–7.6 % / 5.8–6.0; 26–27 % / 8.6–8.8. Barely helps: the die it can catch is rarely the one that sets threat or damage.
    - **B** discard the highest dice whose sum fits the shield (greedy): within 0.5 pp of A. The extra small dice it catches don't matter.
    - **C** discard up to one breath and one weapon die ≤ shield: threat as weak as A, but the best defence vs armed foes (taken 3.3 vs Lurker, 5.4 vs strong with d8). Nothing extra vs natural weapons (one pool).
    - Takeaway: discard-if-≤ rarely touches the highest die, so it can't win threats; lowering the highest die (H) or several dice (M-each) does. C could pair with H (lower threat + catch a weapon die) if shields should be more defensive.
  - Different feel: "blow shatters" (shield ≥ final injury → 0, mark the shield) — protects without helping to win the threat.

## Decisions
- **WIP 5 is the only rules source**; WIP 1–4 are discarded. WIP 5 is partly outdated: ask when unclear.
- Exchange steps (2026-10-20): stateless resources in `story/fight/steps/`, game logic only; `Story` presents them by class and side. Order authored in `exchange_steps.tres` (one `.tres` per step and side); optional steps skip via `applies()`. The outcome always comes last, so it lives in `Fight.end_exchange()`. Ties get their own `TieStep` line (most extreme case: every stance works with the full threat). A side's breath dice must be lost before its incapacitation save (guarded by `fight_steps_test`).
- No async code in the story flow (2026-10-20): waiting is done by `EventQueue` (`queue_delay`, `queue_until`), callers stay synchronous.
- Exchange order (2026-10-19): rolled dice / threat → unnerving → dice evaluated (losses, wield) → (shields) → armour → injuries → outcome; each step typed out, then the reveal delay. Success/failure sound at the dice evaluation.
- **Vantage** = how much the threat was won by (code name; was "margin"). A tie gives no vantage: stances work with the full threat, abilities don't change it.
- Stances are strategies on the attribute (`CharacterAttribute.fight_stance`, text in `FightStance.description`, overridable per decision via `stance_descriptions`); ability text stays in the attribute `.tres`.
- Nerves target is picked **before** the roll. Monster Nerves targets are fixed by the attack (`NervesAttack.target`).
- Unarmed = Guts (player and monster); flee = Blood and always escapes, unless the player collapses (→ lost).
- Monsters without weapons have **natural weapons** (breath dice = weapon dice, never marked, no wield check); armed monsters use their first usable weapon.
- Equipment: profile pattern (`XProfile` → `X`), `static func create()`, modifiers applied when handed out (characters: one list per kind; monsters: one list for all).
- Several weapon dice (Veteran): only one counts: most damage, then least harm to the weapon, then lower result; the rest never mark.
- Armour: wield check first; blocked results mark the attacker's weapon and one random blocking piece; Gambeson −1 last.
- Shields (2026-10-22): voluntary, the die takes its result off the blow; every raise marks; forced above Guts ruins. Rule H is gone.
- Origin abilities are strategies (`Ability`); plain text abilities are an `Ability` with only a description.
- A beaten monster (fight won, or failed incapacitation save) stays incapacitated until the story decides (e.g. kills it); content asks via `AdventureMonsterCondition`.
- Incapacitation: an injury that leaves any effective score ≤ 0 → Guts save vs total injuries (player: save page with the normal dice selection, also while fleeing; monster: all breath dice). Failed = out, like 0 breath.
- Monsters are `Node`s under `Story` (`Monsters`); identity = spawning page + profile + index. Breath dice reset between fights; injuries persist.
- Draw → `draw_transition`; flee button text = `flee_description` (default "Flee!").
- Tests use test-owned characters and monsters (`TestCharacters`, `TestMonsters`); only content suites load game data.
- Open for playtesting: weapon dice above Guts "still hit but get marked" instead of discard (user expects it to make the game worse).
- `Character` and `Monster` share the base class `Actor` (2026-10-20): breath dice, injuries, gear, `get_score()`. Fight steps use `get_actor(fight)` instead of branching on the side.
- Superseded: tie = full margin for both (now: no vantage, stances use the full threat); every weapon die checked individually (now: one is chosen); `MonsterProfile.nature` (now `attack`); incapacitated = out of breath only (now also the failed save).

## Fight Lab (editor plugin, started 2026-10-23)
- `addons/fight_lab`: bottom-panel dock. A headless Godot child process (`fight_lab_runner.tscn`, so autoloads exist and the editor stays responsive) runs what `user://fight_lab/settings.tres` says and writes `user://fight_lab/result.json`.
- **Scenario** (`FightLabScenario` .tres) = who: `side_a` and `side_b`, each a list of `ActorProfile`s (characters or monsters, any mix), plus `strategy_a` / `strategy_b`: a `FightLabStrategy` for the characters on that side (stance, Nerves target, breath dice AUTO / ALL_IN, flee at N breath dice (side A only), weapon / shield / armour tactics; the incapacitation save is rolled all in). Monsters fight as their profile says. Outcomes and records are from side A's view; with no player, texts are third person ("Dorian threatens…"). Profiles that can't fight (characters without rolled attributes) are skipped and listed. Lab-owned fighters: `addons/fight_lab/fighters/` (Armed Dorian: Sword, Buckler, Gambeson, Helmet). Example: `scenarios/example.tres`.
- **Run settings** (`FightLabRunSettings`, set in the dock, kept for next time) = how: many fights or one fight, fights per pairing, max exchanges, seed, optional sweep (`FightLabAttributeSweep`: an attribute of the side A or B fighter; `FightLabForcingSweep`: side A characters' weapon / shield `max_overshoot`), the shown sections.
- **Many fights:** matrix (characters × monsters, cells coloured by win share). Row header = one fighter of side A against all of side B; column header = all of side A against one of side B; cell = that pairing's distributions (or its sweep values); Ctrl+click cells = side by side. With a sweep, comparisons show one sweep value (picker).
- **Sections** (checkboxes, only change what is shown; every number is always recorded): Outcome · Cost of a win (injury taken, breath dice spent, in won fights) · Damage & breath (dealt / taken per fight; breath spent / kept / foe keeps) · Fight length · Gear wear (marks; ruined / dropped).
- **One fight:** threat, breath dice and injuries per exchange as charts, plus the game's exchange log.
- **Distributions (2026-10-25):** comparison views (row, column, Ctrl+click, sweep values) show box plots (median, middle half, 10th–90th percentile) for damage, breath, fight length and the cost of a win, from the per-cell histograms. A cell's detail view adds the outcome split by fight length, injury taken and breath dice spent (stacked, shares of all fights; `by_outcome` in `FightLabStats`).
- First numbers (2026-10-23, default strategy, 200 fights): Dorian wins 10% vs Goblin, 26% vs Lurker, taking ~3.5 injury in the fights he wins; Armed Dorian wins 99–100% at almost no cost.
- 2026-10-24: `Fight` generalised to two `Actor`s (`FightPlan` per side, gear on `FightSide`, `Fight.player` for the story); `ActorProfile` base for both profiles. Side effect fixed: origins' lost-breath rules (Peasant) now apply in fights (`Actor.get_lost_breath_dice`). Mixed run (200 fights): Goblin beats the Lurker 58%, loses to Armed Dorian 99%.

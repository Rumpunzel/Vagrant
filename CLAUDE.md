# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Vagrant" is a Godot 4 (GDScript, Forward Plus, `config/features` = 4.6) digital prototype of a pen & paper RPG: a choose-your-own-adventure with dice checks, combat, character creation (2d6 attributes, two origins, rare origin per double) and a "breath dice" exhaustion mechanic. `obsidian_vault/Vagrant/` holds the tabletop rules/design notes (WIP 1–5); consult it for game-rule intent. WIP 5 is the only valid rules source (WIP 1–4 are discarded); `WIP 5/Rules Reference.md` is the concise reference of the rules as implemented — keep it updated.

## Running

No Godot binary is on PATH. Use 4.6: `/f/Users/Kesepian/Godots/versions/Godot_v4_6-stable_win64_exe/Godot_v4.6-stable_win64.exe`. `.vscode/settings.json` (local, ignored) points the VS Code Godot tools at it; older versions give bogus parse errors (missing UIDs).

- Run game: `<godot> --path .`
- Open editor: `<godot> -e --path .`
- Smoke check (loads autoloads + main scene, prints script errors): `<godot> --headless --path . --quit-after 300`. `--check-only --script` skips autoloads and reports false errors. Don't start a second `--editor` while the user's editor is open.

Tests are gdUnit4 suites (`addons/gdUnit4`, `extends GdUnitTestSuite`, `test_*` funcs), split in two: `tests/unit/` (no waiting, no scenes/UI — keep it that way) and `tests/integration/` (anything that awaits timers/typing/fades or runs the Story scene or UI). Run headless: `GODOT_BIN=<godot> bash addons/gdUnit4/runtest.sh -a res://tests/unit --ignoreHeadlessMode` (or `res://tests/integration`, or `res://tests` for both) (exit 0 = pass, 100 = failures, 101 = only warnings such as orphan nodes; a "Remote Debugger … port 0" error at start is harmless). Reports go to `reports/` (gitignored). `tests/mute_audio_hook.gd` (a gdUnit session hook) mutes the Master bus while tests run. Fight tests build fixed dice/scores via `tests/unit/fight_test_dice.gd` (`FightTestDice`). Tests don't load game content (monsters etc.) unless they check that content on purpose (e.g. `lurker_ambush_test.gd`): use the test-owned monsters in `tests/test_monsters.gd` (`TestMonsters`) and characters in `tests/test_characters.gd` (`TestCharacters`), so rebalancing the game doesn't break tests. gdlint allows max 25 public methods per class (so 25 test functions per suite); split suites by topic instead of raising the limit. CI (`godot-gdunit-labs/gdUnit4-action`, Godot version must match `project.godot`, also `GODOT_VERSION` of the script check job): `.github/workflows/tests.yml` runs lint, the script check and `tests/unit` on every push (which covers PR commits); `integration_tests.yml` runs `tests/integration` only on pull requests into `main` or by hand (Actions → Run workflow). gdUnit's `is_equal`/`contains` on objects compare **properties**, not identity — use `is_same`/`is_not_same` when identity matters (e.g. two fresh monsters of one profile look equal). gdUnit can print a green summary even when project scripts fail to compile — also grep its output for `SCRIPT ERROR` and run the smoke check. New `class_name`s only resolve after an editor rescan (`<godot> --headless --path . --editor --quit`, only while the user's editor is closed). Lint: `gdlint .` (gdtoolkit 4.5.0, config in `gdlintrc`: line length 240, only the vendored addons (and the collapsible container's examples) excluded by directory name, so `fight_lab`, `adventure_editor` and `collapsible_container` are linted; also runs in CI). Script check: `<godot> --headless --path . res://tests/script_check.tscn` loads every script of ours so each compiles (the editor scan and the tests only compile what they load); CI's "Script check" job runs it plus the smoke check and fails on `SCRIPT ERROR` / `Parse Error`. Don't use `gdformat` — it would rewrite almost every file against the project's one-liner style. gdlint cannot parse `if a: x() else: y()` inside a one-line lambda; write such lambdas over several lines or use a method. GDScript warnings are configured strictly in `project.godot`: **untyped declarations are errors**, inferred (`:=`) declarations and unsafe access/casts/calls are warnings. Always use explicit types (`var x: int = 0`, typed loop vars `for c: StoryChoice in ...`, typed arrays/dictionaries).

Debug inputs: Backspace = restart game, Escape = restart current story (`main.gd`), R = `debug_random`.

## Architecture

**Autoloads** (`project.godot`): `Main` (scene flow), `Rules` (die types d4–d12, starting `BREATH_DICE`, the three `ATTRIBUTES` as preloaded resources), `DiceRoller`, `DiceRollSounds`, `Stage` (persistent background/ambience/music CanvasLayer), `BlurLayer`, plus tooltips_pro managers.

**Scene flow**: main scene (`game/game.gd`) → `default_adventure.start_adventure()` → `Main.enter_story()`. If the adventure's protagonist `CharacterProfile` is not valid, character creation runs first; then the Story scene is loaded and `Story.start_adventure()` is called. Scenes are referenced by `uid://` strings and loaded via `Files.load_async`.

**Data vs. runtime split** — the central design:
- `adventure/` = authored **Resources** (`.tres`). `Adventure` → `AdventurePage` with `AdventureDecision`s (plain, dice, save, fight; `@tool`, each describes how it ends with `get_outcomes()`, which `Fight`, `StorySaveDecision` and the adventure editor all go by), `AdventureConsequence`s, `AdventureCondition`s, and nested `events` (sub-pages whose prerequisites decide whether they override/append title, description, background, ambience; controlled by the `Exclusivity` flags). An `AdventureEventScenario` in `events` shows at most one of its own events (the first whose prerequisites are met). Events should work on any page: `AdventureHostReference` ("↺ Host") leads back to the page the event was shown on (`Story.get_host()`), `AdventurePreviousLocationReference` to where the player was before it (fleeing; Story goes back past the host, `Story._go`); monsters belong to the event that spawned them, shared by all its hosts unless the event is `generic`. An event's `nearby_events` show on the locations around wherever it is placed, within their `nearby_reach` (`AdventurePage.find_nearby_events`, `Story.get_nearby_events`). Pages link via `AdventurePageReference`: either an `AdventurePage` directly or an `AdventureTransition` holding a file path (lazy loads to avoid cyclic resource references). Content lives in `adventure/adventures/locations/<area>/`.
- `story/` = **runtime** RefCounted mirrors built per visit: `Story` (scene node) turns an `AdventurePage` into a `StoryPage` with `StoryChoice`s, tracks `_page_stack`, `_page_log` (visit counts) and `_decision_log`. A decision without a transition goes back one page; dead-end pages get `AdventureDecision.get_turn_back()` ("Turn back."). Choices are resolved through an `EventQueue` (consequences, delay, then `enter_page`). Dice/save/fight checks are message objects in `story/messages/` (`DiceRequest` subclasses → `*Result`).
- `characters/` = character data resources (`ActorProfile` → `CharacterProfile` / `MonsterProfile`, `Origin`/`Background`, `Ability`, `CharacterAttribute`) and runtime `Actor` → `Character` / `Monster`, `Party`. A `Fight` is between two `Actor`s; each side's exchange comes from a `FightPlan` (the player's `FightRequest`, `Monster.get_fight_plan()`, or a Fight Lab strategy). `Fight.player` (story only) is the side whose choices are asked for and whom texts call "you".
- `dice/` = `Die`, `DieType` resources, `DiceRoller`, dice log UI.
- `game/` = UI scenes (story book, character sheets/creation, breath dice selection, stance selection, mechanics like catch breath / make camp, stage).
- `custom_nodes/` = reusable generic Controls and helpers (`Files`, `EventQueue`, `SkippableTimer`, `TypingLabel`, ...).

**References use UIDs**, not paths (`uid://…` in `ext_resource`s, `AdventureTransition._leads_to`, `load()`/`preload()`; in tests with the file name as a trailing comment). Only directories keep `res://` paths. Exception: gdUnit session hooks in `project.godot` (`gdunit4/hooks/session_hooks`) must use `res://` paths. New files get a UID from the editor, or `ResourceUID.id_to_text(ResourceUID.create_id())`.

**Saving resources from a script:** `ResourceSaver.save()` outside the editor drops all `uid=` attributes (header and `ext_resource`s), which breaks `uid://` references to that file. Prefer editing in the editor; otherwise restore the UIDs (scripts: `.gd.uid`, textures: `.import`, `.tres`/`.tscn`: their header) and check the diff.

**Load-cycle trap:** `Rules` preloads the attribute/die `.tres` as consts. Anything those resources' scripts reference (e.g. `CharacterAttribute.fight_stance` → `FightStance`) must not reference `Rules`, `Die`, or fight/story classes, or `Rules` fails to compile ("Could not resolve external class member STRENGTH"). The `Main` autoload reaches `CharacterProfile`, so profiles must not name `Actor`/`Character`/`Monster` or `Rules`' die types either (symptom: "d4.tres Parse Error" and "Cannot assign … to constant d4"); load such resources at runtime.

Many scripts are `@tool` and use `@abstract` classes; setters guard with `Engine.is_editor_hint()`. Node wiring is done through `@export` vars in a "Configuration" export group rather than `$` paths.

**Addons**: `collapsible_container` (enabled editor plugin, originally third-party but changed by us, so linted except its `examples (OPTIONAL)`), `tooltips_pro` (enabled editor plugin), `godot-git-plugin`, `gdUnit4` (vendored); `fight_lab` (bottom panel) and `adventure_editor` (main-screen tab "Adventure": map of one adventure, plan and design in `addons/adventure_editor/PLAN.md`) are ours. Treat the other third-party addons as vendored.

Folder colors in `project.godot` mirror this layout (adventure orange, characters yellow, dice purple, game green, story blue).
